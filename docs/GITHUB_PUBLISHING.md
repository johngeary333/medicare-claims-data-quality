# Publish this project on GitHub

## Which archive should I use?

- **`medicare_claims_portfolio_GITHUB_READY.zip`**: Extract **this** ZIP and publish the `medicare-claims-data-quality` directory in your GitHub repository. It contains real, already calculated aggregate results, code, report, chart, and tests. It contains **no artificial demonstration results** and intentionally omits raw claim-level CSVs and the local SQLite database.
- **`medicare_claims_portfolio_LOCAL_WITH_CMS_DATA.zip`**: Keep this as your private working/reproducibility copy. It includes the two real synthetic CMS source CSVs and the local derived SQLite database. **Do not upload the whole local archive to GitHub.**

The CMS sample records are synthetic public-use data, not actual beneficiaries; we keep the row-level material out of GitHub to limit repository size and foreground the analytical workflow.

## Browser upload (no Git commands needed)

1. Sign in to [GitHub](https://github.com/) and choose **New repository**.
2. Name it `medicare-claims-data-quality`. Use a short description such as "Reproducible SAS and SQL analysis of CMS synthetic Medicare inpatient claims."
3. Create an **empty** public repo. For easiest upload, do *not* add a separate README, `.gitignore`, or license during setup, because those are already in the project files (a license is optional and not included).
4. Extract the **GitHub-ready ZIP** on your PC. **Open the extracted `medicare-claims-data-quality` folder.**
5. In the new repo, click **Add file → Upload files**, and drag in the *contents* of the extracted folder (including `.gitignore` and its subfolders). Some browsers do not include hidden files when dragging a folder; if so, add `.gitignore` separately or use Git/VS Code to push the directory.
6. Commit with a message like `Add CMS Medicare claims data quality portfolio`.
7. Open the repository `README.md` and verify that the chart and [full report](../reports/real_cms_sample1_2008_report.md) appear correctly. Verify that `data/raw` contains no `.csv` and `data/processed` contains no `.sqlite`.
8. Add the repository URL to the **Projects** section of your resume and LinkedIn.

If your browser upload limits the number of files or does not preserve directories, the Git CLI method is:

```powershell
cd path\to\medicare-claims-data-quality
git init
git add .
git commit -m "Add Medicare claims analytics portfolio"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/medicare-claims-data-quality.git
git push -u origin main
```

Git may ask you to sign in. Replace `YOUR_USERNAME` with your own GitHub username.

## What can I accurately say about the analysis?

The verified results in the report were generated by **Python and SQLite against the two actual CMS DE-SynPUF files**. The `.sas` files are source code you can run in SAS Studio Online to reproduce import checks, cleaning rules, and summary tables. **Do not claim that the full SAS workflow was executed until you personally run scripts 01 and 02 and verify the results.** You already checked the import row counts in SAS.

Use a resume bullet like this after verifying your SAS results:

> Analyzed CMS synthetic Medicare inpatient claims using SAS and SQL, validating 27,701 2008 claim-segment records and documenting missing utilization values, negative payments, and data linkage quality.

The synthetic sample does not support conclusions about real Medicare costs, utilization or infection risk.
